# 彩排 · Rehearsal

> 难开口的话，先彩排一遍。为重要对话做练习的本地工具：整理你对 TA 的了解，和「TA 的模拟」把那段话先说一遍，再用真实反馈修正理解。**本地优先，只辅助理解与表达，不提供操控。**

## 这是什么

面对一场重要的对话（道歉、表白、化解冷战、谈薪、摊牌），你有没有想过"如果能先排练一遍就好了"？

**彩排**做的事：

1. **整理你对 TA 的了解** —— 导入聊天记录（或手动存证 / 通过 24 问访谈口述），AI 归纳出一份**理解卡**：基础信息（TA 站在哪里）、生活结构（TA 长期能做什么）、人物性情（TA 怎样理解事情）、场景表达（TA 如何开口与行动）。
2. **和「TA 的模拟」彩排** —— 选一个场景开始彩排。模拟由理解卡与事件记忆生成：卡越准、记越多，模拟越接近。TA 可以沉默、追问、拒绝、继续过自己的日子。
3. **写下预判 → 对照现实** —— 彩排结束前写下预判（2~4 个带概率的心理假设）；拿到 TA 的真实反应后粘贴回来，AI 做**差异分析**（命中/事实错/材料缺/性情错/表达偏/**扮演偏差**），对理解卡做**可撤销的最小修正**。修正幅度按证据强度分级（学习率 α）：错得越离谱改得越多，单次命中只微调——防止过拟合于偶然。
4. **事件记忆** —— 每场彩排复盘和每次现实对照会自动提取「发生过什么」存成事件段（向量化，本地优先）。下次开场时，相关往事会自动注入，让模拟记得你们之间发生过什么。
5. **想多了解的** —— 理解卡的空白与待验证项变成下次真实聊天时可以自然求证的话题。
6. **预判校准** —— 预判概率与真实结果持续对照，计算 Brier 分数：你的模型说 65% 的事到底发生没发生，数据会告诉你它是否系统性过自信。

**核心纪律（来自人物理解写法）**：不为角色预写答案，只建立让 TA 能在陌生情境中继续生活的最小条件；写倾向、不写唯一答案；不知道的留白，不脑补；每条推断可溯源、可撤销；**模拟没演好（扮演偏差）不怪理解卡**——两类错误分开记。

## 安装

从 [Releases](../../releases) 下载对应系统安装包：

| 系统 | 文件 | 状态 |
|---|---|---|
| Windows | `Rehearsal Setup <版本>.exe`（NSIS 安装向导）/ `*.zip`（便携版） | ✅ 已提供 |
| macOS | `Rehearsal-<版本>.dmg`（Intel 与 Apple Silicon） | ⏳ 由 CI 构建，见 [docs/enable-ci.md](docs/enable-ci.md)（三条命令启用） |
| Linux | `Rehearsal-<版本>.AppImage` / `*.deb` | ⏳ 同上 |

> 安装包未做代码签名（个人开源项目），Windows SmartScreen / macOS Gatekeeper 可能提示，选择"仍要运行"即可。
> Release 页附 `SHA256SUMS.txt` 校验和（CI 构建产物）。

**首次使用**：应用默认运行在**演示模式**（离线内置样例回复，全流程可体验）。要接真实模型，到「设置」选择接入格式并填入密钥即可（设置页无需先建人物）。

**从旧版本升级**：数据目录保持不变，老档案无感延续；旧版导出的卡片文件可直接导入。

## 支持的 API 接入格式

| 格式 | 适用服务商 | 认证方式 | 模型列表 |
|---|---|---|---|
| **OpenAI 兼容**（Chat Completions） | OpenAI、DeepSeek、Kimi、智谱 GLM、通义 Qwen、OpenRouter、OneAPI/NewAPI 等中转网关 | Bearer Key | ✅ 一键拉取 |
| **Azure OpenAI** | Azure 云上的部署 | api-key 头 + 部署完整地址 | 部署制（不适用） |
| **Anthropic Claude** | Claude 系列官方 API | x-api-key + anthropic-version | ✅ |
| **Google Gemini** | Gemini 官方 API（原生 generateContent 协议） | x-goog-api-key | ✅（过滤非文本模型） |
| **Ollama 本地模型** | 本机/局域网 Ollama，**完全离线** | 无需密钥 | ✅ |
| **演示模式** | 无网络环境体验流程 | 无 | 内置样例 |

- 设置页可一键「获取模型列表」直接下拉选择；连接测试逐步排查（密钥/地址/限流均有中文提示）。
- 主流中转网关（OneAPI/NewAPI/SillyTavern 反代等）一律选 OpenAI 兼容格式。
- **事件记忆向量化**支持单独配置 Embedding 来源（OpenAI 兼容 / Ollama / Gemini）；选择 Ollama（如 `nomic-embed-text`、`bge-m3`）可全程不出本机。
- 最在意隐私的搭配：**Ollama 本地模型 + 彩排本地存储 = 全程不出本机**。

## 功能总览

```
导入素材 ──→ 原话库 ──→ AI 归纳 ──→ 理解卡（四层 + 动态状态）
  ↑                                │
  │                                ├─→ 彩排（TA 的模拟 + 事件记忆 + 复盘报告）
24 问访谈（冷启动口述）────────────┤
  │                                ├─→ 对照复盘（写下预判 → 现实对照 → 差异分析 → 卡片更新）
  └──→ 空白/待验证 ──→ 想多了解的 ←─┘
```

| 模块 | 说明 |
|---|---|
| **导入** | 支持 [留痕 MemoTrace](https://github.com/LC044/MemoTrace) / WeChatMsg 的 JSON·CSV·TXT、QQ 导出工具的时间戳 TXT、微信合并转发复制文本、通用 JSON/JSONL、自由粘贴。解析完全在本机，支持"我的昵称"标记本人、GBK 自动检测 |
| **原话库** | 所有推断的唯一事实来源。只存证不评论；每条证据有编号（E#），AI 的归纳必须引用编号 |
| **理解卡** | 四层认知条目，每条带认识层级（事实/推断/空白）、来源（证据/用户陈述/AI推断）、把握度；易过期信息只进"动态状态"层；发给 AI 的最小卡片可预览、可导出 JSON |
| **24 问** | 人物观察版的结构化口述访谈：核心特质收敛 → 分化与反向 → 信念分层 → 情绪ABC → 循环与决策。抽象回答会被追问"具体会怎么做"；跳过=暂未确定；最终整合可勾选写入理解卡 |
| **彩排** | 场景模板（日常/约会/冷战/道歉/重要谈话/请求）或自定义。分"情境设定"（TA 可感知）与"彩排目标"（仅复盘可见）。相关往事自动注入；结束生成复盘报告：六个观察指标 + 你的沟通复盘 + 下轮建议 + 现实验证清单 |
| **对照复盘** | 预判冻结 → 现实对照（原话优先，自动存证 + 入事件记忆）→ 差异分析（含扮演偏差归类）→ 卡片最小修正（学习率 α 分级，可一键撤销）。统计：Top1/Top2 命中率、Brier 校准、对照完成率 |
| **事件记忆** | 彩排与现实事件段向量化存储；可查看、可单删、可清空、可重建索引；换 Embedding 模型后自动提示重建 |
| **想多了解的** | 理解卡空白 + 用户陈述待验证 + 访谈待确认 → "下次可以了解 TA 什么" |
| **状态栏** | 游戏风格的人物速览：档案槽位（性别/生日/职业/家庭/爱好/喜爱的食物等，AI 提取 + 手动编辑）、成长阶段（初见→同频）、五条数值条、四层分布、最近动态与彩排 |
| **深度分析** | 对这个人或某个场景的完整分析：本地统计（素材月度分布/彩排/预判命中/记忆）+ AI 整合报告；场景推演给出反应路径（带可能性）、相关往事、最优策略，可一键转入彩排 |

## 方法论映射（人物理解写法 → 产品纪律）

| 方法论原则 | 产品实现 |
|---|---|
| 理解卡=最小生成条件，不是全量画像 | 空白层不进卡；把握 <0.3 不进卡；每层 ≤8 条、总量 ≤28；可预览注入内容 |
| 静态人设与动态事实分离 | 易过期信息只进"动态状态"，可"翻篇"；防止关系倒退/情绪过期 |
| 写倾向，不写唯一答案 | 归纳与假设强制倾向措辞（往往/容易/更愿意），禁"永远/绝不" |
| 标签必须附带具体含义 | 追问引擎：抽象标签 →"具体会做什么"→"为什么这是 TA 的" |
| 推断可溯源、不脑补 | 条目必须挂证据编号 / 用户陈述 / AI推断；无溯源不得为"事实"；记忆条目同理 |
| 示例教表面文风（防复读/旁白/补造） | 模拟禁内心独白；卡内标注[事实]/[推断]区分可靠度；防误读护栏 |
| 六个观察指标 | 复盘报告的固定评估框架；扮演偏差单独归类不污染命中率 |
| 心理分析=行为推测，决策权在用户 | 多假设+概率+验证方式；差异分析改卡可撤销；学习率 α 让修正幅度与证据强度匹配；"推断不是真相"贯穿文案 |

详见 [docs/methodology.md](docs/methodology.md)。

## 隐私与红线

- **本地优先**：档案、证据、彩排、访谈、事件记忆全部数据只存在本机数据目录，删除档案即全部删除。
- **如实告知**：配置在线模型后，理解卡与相关对话文本会发送给你所配置的模型服务商处理；事件记忆同理发送给你配置的 Embedding 服务商（可选 Ollama 全本地）。API Key 经系统级加密保存（Windows DPAPI / macOS Keychain / Linux libsecret；系统密钥服务不可用时会明文保存并在设置页明示）。
- **知情提示**：导入第三方聊天记录时应用内明确提示——仅用于自我理解与沟通练习，勿导入你无权处理的对话。
- **拒绝操控**：引擎级硬过滤操控/打压/煤气灯类请求（场景、消息、反馈三条通道），并提供"诚实表达自己需求"的替代方向；禁止输出临床诊断标签。
- **防自我欺骗**：差异分析里"证明你错了"的记录永远保留（可撤销但可见）；命中率统计不被扮演偏差污染。
- **心理分析不是诊断**：所有心理输出都是行为推测 + 把握度 + 验证方式。它帮你理解与表达，不定义 TA 是"什么病"。

## 开发

```bash
git clone https://github.com/Theater-ahyeon/rehearsal.git
cd rehearsal
npm install          # npmmirror 镜像配置见 .npmrc
npm start            # 启动应用（演示模式）
npm run web          # 或以纯 Web 宿主运行（127.0.0.1:4173，与桌面版共用数据目录）
npm test             # 单元测试（53 个，无需 Electron/GUI/Key）
npm run dist         # 本地构建 Windows 安装包（nsis + zip）
```

技术栈：Electron 33 · 原生 HTML/CSS/JS（无构建步骤）· JSON 本地存储（原子写入 + 启动对账）· 多协议 LLM 接入（OpenAI 兼容 / Azure / Anthropic / Gemini / Ollama + 离线 mock，适配器架构）· 事件记忆向量检索（服务商 embedding + 本地词面降级）。业务核心（store/parser/llm/prompts/pipeline/memory）与 Electron 解耦，可在纯 Node 环境测试。

### 项目结构

```
src/
  main/          # 主进程（无 Electron 依赖的纯 Node 模块 + main.js IPC 编排）
    store.js     #   本地存储：JSON 原子写入、索引对账、统计（命中率/Brier）
    parser.js    #   聊天记录导入解析（JSON/CSV/TXT/微信合并转发）
    llm.js       #   多协议 LLM 适配器（openai/azure/anthropic/gemini/ollama/mock）+ JSON 提取
    prompts.js   #   全部提示词：理解卡编译、模拟、归纳、复盘、假设、差异分析、24 问、红线、事件提取
    memory.js    #   事件记忆：向量化（服务商 embedding + 本地词面降级）、余弦检索、ledger 防重
    pipeline.js  #   业务流：归纳→彩排→预判→现实对照→差异分析→撤销、访谈
    main.js      #   Electron 窗口 + IPC（安全基线在此；数据目录钉住保证改名后档案延续）
  preload.js     # contextBridge IPC 白名单暴露
  renderer/      # 无构建 SPA（index.html + 分层 css + 模块化 js）
tests/run.js     # 单元测试（node tests/run.js）
docs/            # 每轮开发进度文档 + 方法论 + 格式说明
build/           # 图标与生成脚本
```

### 安全基线

contextIsolation + 无 nodeIntegration + CSP（script-src 'self'）· IPC id 严格校验（UUID 正则 + 路径穿越防御）· 渲染层全量 HTML 转义 · 窗口导航/弹窗拦截 · 单实例锁 · 提示注入防御（素材=数据非指令 + 无溯源不得为事实）。详见 [docs/round-03-adversarial-review.md](docs/round-03-adversarial-review.md)。
