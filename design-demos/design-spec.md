# 生境沙盒 · 前端重构设计方向探索 · 设计 Spec

> 本文件是三个独立设计方向的唯一共同输入。每个方向只看这份 spec，互不参考。

## 一、产品是什么

「生境沙盒 Habitat Sandbox」——基于 AIRP「人物生境写法」的**本地优先**桌面应用（Electron，主窗口逻辑分辨率 1440×900）。用户为一个真实的人建立「生境档案」（数字孪生）：导入聊天记录 → AI 归纳出**四层生境卡**（基础信息 / 生活结构 / 人物性情 / 场景表达）→ 在沙盒里与「她」彩排一段重要对话（道歉、表白、化解冷战、谈薪）→ 演练前冻结**预测单**（2~4 个带概率的心理假设），事后把她的真实反应粘贴回来做**差异归因**，对卡片做可撤销的最小修正。

八个功能模块（导航用真实名称）：人物、生境卡、证据库、导入、24问访谈、演练、校准闭环、设置。

产品红线与气质来源（设计要体现这些纪律，不是装饰）：
- **最小生成条件**：卡片是倾向不是台词库；每条带认识层级（事实/推断/空白）与置信度；
- **留白是允许的**：不知道的就明示「空白」，不脑补；
- **推断不是真相**：所有心理输出都是行为推测 + 验证方式；
- **她不知道这是演练**：场景设定（她可感知）与演练目标（仅复盘可见）严格分离；
- **本地优先**：数据只在本机；演示模式完全离线可用。

## 二、受众、场景与情感基调

单用户本地工具，多在**夜晚独自**使用，面对「该不该说、怎么说」的紧张与事后复盘。基调关键词：**冷静、私密、可信、克制的人文感**——像一间安静的排练室或一本私人笔记本，而不是社交产品、黑客工具或医疗产品。

必须避免的气质：监控感（她在被分析的对象感过重）、临床诊断感、游戏化轻浮感、企业 SaaS 后台感。

## 三、输出格式与尺寸（硬约束）

- **纯 HTML/CSS 单文件**，可内嵌少量内联 SVG，**不用任何外部图片/外链字体文件**（可用系统字体栈或 Google Fonts 在线引用均可，但断网时不得破版）；
- 渲染视口 **1440×900**，画面 = 应用整窗内容（无需画 macOS/Windows 窗口标题栏 chrome）；
- 所有文字必须是下方「真实内容」的中文，禁止 lorem ipsum、禁止编造英文假数据；
- 可读性硬底线：正文 ≥14px、辅助标签 ≥12px、文字对比度 ≥4.5:1；留白必须是有视觉锚点的构图，不是内容缺席。

## 四、每版必含的真实内容（三版一致，只换设计）

**主画面统一为「演练」视图**（产品核心场景），必须包含以下五组内容：

1. **应用框架**：八个导航项（人物、生境卡、证据库、导入、24问访谈、演练、校准闭环、设置），其中「演练」为当前项；侧栏或角落显示当前人物「林晚」；底部有「演示模式（离线）」状态。
2. **场景设定区**：场景「道歉 —— 为三个月前的那次争吵」；两行元信息：「情境设定：她可感知」／「演练目标：仅复盘可见，她不知道这是演练」；提供「结束演练并生成预测单」主按钮。
3. **对话流（数字孪生）**：
   - 我：「那天是我不对，话说重了。这半年我一直在想这件事。」
   - 她（孪生 · 林晚）：「你现在来说这个，是因为快过年了吗？」
   - 我：「有一部分。但主要是，我一直记得你当时没说完的那句话。」
   - 她：「嗯。」（旁注小字：她可以沉默、追问、拒绝——卡内标注 [推断]）
   - 底部输入框占位：「说点什么……」
4. **她的生境速览**（体现四层生境卡，每条带徽章）：
   - 基础信息：林晚 · 26 · 出版业编辑 ［事实 · 引用证据 ×12］
   - 人物性情：面对道歉往往先确认动机，而非先接住情绪 ［推断 · 置信度 0.62］
   - 场景表达：短句、常省略主语；「嗯」未必是同意 ［推断 · 置信度 0.55］
   - 空白：她与父亲的关系 —— 未知 ［空白 · 留白是允许的］
   - 防误读护栏小字：卡片是倾向，不是台词库。
5. **预测单入口**（页面某处）：「演练结束前冻结预测」：她先追问动机而非接受道歉 65% ／ 她用反问确认我的真实来意 55% ／ 她不会当场和好，但会保留对话渠道 80%。

## 五、视觉母题假设（从内容长出来，任选其一深耕，不要全用）

- 「生境 / 栖息地」：一滴水（现 logo）、微缩生态、培养皿、标本卡、水文图；
- 「四层」：地层剖面、分层标本盒；
- 「证据 E#」：档案编号、引注、脚注系统；
- 「留白」：版面上明确存在一格「已知 / 未知」的留白表达。

## 六、布局骨架互异（三版硬要求）

三个方向在以下至少一项必须**结构性不同**（不许只换配色字体的换皮）：
① 导航形态（左侧栏 / 顶部横栏 / 其他组织方式）；
② 对话区与「生境速览」的空间关系（双栏 / 单列卡片流 / 浮动抽屉 / 上下分区）；
③ 场景设定与预测单的组织方式（内嵌头部 / 独立阶段条 / 侧挂面板）。
交付时在 HTML 注释里自述本版的结构选择。

## 七、反 AI slop 禁区

紫渐变；emoji 当图标；圆角卡片+左彩色 border accent；SVG 手画人脸/人物；「均匀深蓝底 + 青/紫霓虹 glow」的 GitHub-dark 偷懒组合；Inter/Roboto 直接作 display 大标题；编造的 stats/quotes 装饰。中文引号用「」。
